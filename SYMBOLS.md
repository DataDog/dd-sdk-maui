# Symbol Upload for Crash Symbolication

The `DatadogSdk.Maui` NuGet package includes an MSBuild target that automatically uploads debug symbols to Datadog after `dotnet publish`. This enables server-side symbolication of native crashes reported by the SDK.

## Prerequisites

Install `datadog-ci` globally:

```bash
npm install -g @datadog/datadog-ci
```

Export your Datadog API key:

```bash
export DATADOG_API_KEY=your-api-key
```

## What gets uploaded

| Platform | File | What it covers | Generated by |
|----------|------|---------------|-------------|
| **iOS** | `.dSYM` bundle | Native crashes + AOT-compiled C# method names | `dotnet publish -r ios-arm64` |
| **Android** | `mapping.txt` | R8/ProGuard obfuscated Java/Kotlin class and method names | `dotnet publish` with `AndroidLinkTool=r8` |

Portable PDB files (C# source file + line numbers) are **not uploaded**. They are resolved on-device by the .NET runtime when a managed exception is caught. No server-side processing is needed for managed C# stack traces.

## Quick start

### iOS

```bash
dotnet publish -c Release -f net10.0-ios -r ios-arm64 \
  -p:DatadogUploadSymbols=true
```

### Android

```bash
dotnet publish -c Release -f net10.0-android \
  -p:DatadogUploadSymbols=true
```

## Configuration

All configuration is done via MSBuild properties. These can be set in your `.csproj` file or passed on the command line with `-p:`.

### MSBuild properties

| Property | Required | Default | Description |
|----------|----------|---------|-------------|
| `DatadogUploadSymbols` | Yes | `false` | Set to `true` to enable symbol upload after publish |
| `DatadogServiceName` | No | `$(AssemblyName)` | Service name used to identify your app in Datadog |
| `DatadogSite` | No | `datadoghq.com` | Datadog site (e.g., `datadoghq.eu`, `us5.datadoghq.com`) |
| `DatadogApiKey` | No | — | API key passed directly. If not set, the `DATADOG_API_KEY` environment variable is used instead |

### Setting properties in `.csproj`

```xml
<PropertyGroup>
  <DatadogServiceName>my-app</DatadogServiceName>
  <DatadogSite>datadoghq.eu</DatadogSite>
</PropertyGroup>
```

### Setting properties on the command line

```bash
dotnet publish -c Release -f net10.0-ios -r ios-arm64 \
  -p:DatadogUploadSymbols=true \
  -p:DatadogServiceName=my-app \
  -p:DatadogSite=datadoghq.eu
```

## API key

The API key can be provided in two ways:

1. **Environment variable** (recommended for CI):
   ```bash
   export DATADOG_API_KEY=your-key
   dotnet publish -c Release -p:DatadogUploadSymbols=true ...
   ```

2. **MSBuild property** (useful for local testing):
   ```bash
   dotnet publish -c Release -p:DatadogUploadSymbols=true -p:DatadogApiKey=your-key ...
   ```

When using the environment variable, the shell's `DATADOG_API_KEY` passes through to `datadog-ci` automatically. When using the MSBuild property, it is injected into the `datadog-ci` process environment.

**Important:** Do not set `DatadogApiKey` in your `.csproj` file — it will be committed to source control. Use environment variables for API keys.

## Android: enabling R8

By default, .NET MAUI Android Release builds do not run R8, so no `mapping.txt` is generated. To enable it, add the following to your `.csproj`:

```xml
<PropertyGroup Condition="'$(Configuration)' == 'Release'">
  <AndroidLinkTool>r8</AndroidLinkTool>
  <AndroidCreateProguardMappingFile>true</AndroidCreateProguardMappingFile>
</PropertyGroup>
```

The mapping file will be generated at `bin/Release/net10.0-android/mapping.txt`.

## How it works

The `DatadogSdk.Maui` NuGet package ships a `.targets` file (`DatadogSdk.Maui.targets`) under `buildTransitive/`. MSBuild automatically imports it into any project that references the package — no manual setup required.

The targets file defines three MSBuild targets that run after `dotnet publish`:

1. **`DatadogCheckCli`** — Verifies that `datadog-ci` is installed and the API key is available. If either check fails, a message is printed and upload is skipped.

2. **`DatadogUploadDsym`** (iOS) — Locates the `.dSYM` bundle next to the `.app` in the publish output and uploads it via `datadog-ci dsyms upload`.

3. **`DatadogUploadMapping`** (Android) — Locates `mapping.txt` in the build output and uploads it via `datadog-ci flutter-symbols upload --android-mapping`.

4. **`DatadogSymbolReport`** — Prints a summary of what was uploaded (service, version, site, file paths).

### Verbosity

By default, `dotnet publish` uses the .NET terminal logger which hides informational messages. To see the Datadog upload output, add `-v n -tl:off`:

```bash
dotnet publish -c Release -f net10.0-ios -r ios-arm64 \
  -p:DatadogUploadSymbols=true -v n -tl:off
```

## Symbol file locations

After a Release publish, symbol files are located at:

### iOS
```
bin/Release/net10.0-ios/ios-arm64/
  example.app.dSYM/          <-- dSYM bundle (uploaded to Datadog)
  example.app/                <-- signed app bundle
  example.pdb                 <-- portable PDB (resolved on-device)
  publish/
    example.ipa               <-- distributable package
```

### Android
```
bin/Release/net10.0-android/
  mapping.txt                 <-- R8 mapping (uploaded to Datadog, requires AndroidLinkTool=r8)
  publish/
    com.datadog.maui.test.apk <-- distributable package
```

## Troubleshooting

**"Skipping symbol upload — datadog-ci is not installed"**
Run `npm install -g @datadog/datadog-ci` and verify with `datadog-ci version`.

**"Skipping symbol upload — DATADOG_API_KEY is not set"**
Export the key in your shell: `export DATADOG_API_KEY=your-key`. Verify with `echo $DATADOG_API_KEY`.

**"Skipping dSYM upload — file not found"**
dSYMs are only generated for device builds (`-r ios-arm64`). Simulator builds (`iossimulator-arm64`) do not produce dSYMs.

**"Skipping mapping upload — mapping.txt not found"**
Ensure R8 is enabled in your `.csproj` with `<AndroidLinkTool>r8</AndroidLinkTool>` and `<AndroidCreateProguardMappingFile>true</AndroidCreateProguardMappingFile>`.

**No Datadog output visible**
Add `-v n -tl:off` to your `dotnet publish` command to disable the terminal logger and show all build messages.

**Upload seems to work but no symbols appear in Datadog**
Symbols take up to 5 minutes to process after upload. Check **Error Tracking > Settings > Symbol Files** in Datadog.
